Lesson 0001: Cache Keys & Header Signals

Estimated time: 5 minutes • Track: HTTP Caching & Proxy Architecture

1. The Core Idea

A caching proxy acts as an intermediary. When a client requests a resource, the proxy checks whether it already has a saved copy.

Cache Key Equation:
Cache Key = HASH(HTTP_METHOD + ":" + REQUEST_URI)

By default, only safe and idempotent requests (like GET and HEAD) are cached. Mutating requests (POST, PUT, DELETE) modify state and must not serve cached payloads.

2. HIT vs MISS Telemetry

Proxies inform clients where the response originated via standard telemetry headers:

  • X-Cache: MISS — Item was not in store. Proxy forwarded request to origin and saved the response.
  • X-Cache: HIT — Matching entry was found. Proxy returned saved response instantly without touching origin.
